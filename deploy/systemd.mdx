---
title: "systemd"
description: "Run the Zee3 binary as a systemd service on Linux, with the install script or by hand."
---

This runs the [Linux binary](/deploy/install#install-script) as a service under its own `zee3` user.

<Tabs>
  <Tab title="Automatic">
    One command installs `zee3`, sets up the service and starts it:

    ```bash
    curl -fsSL https://raw.githubusercontent.com/terrific-ci/z3/main/install.sh | sh -s -- --service
    ```

    It asks for `sudo` when it needs to, and then:

    - installs `zee3` in `/usr/local/bin`,
    - creates a system user `zee3` and the data directory `/var/lib/zee3`, owned by it,
    - creates the settings file `/etc/zee3/zee3.env` with the root access key `admin` and a **random
      root secret key**, readable only by root and the `zee3` group. An existing file is left alone,
    - writes the unit to `/etc/systemd/system/zee3.service`,
    - enables and starts `zee3`.

    The root credentials are in `/etc/zee3/zee3.env`:

    ```bash
    sudo cat /etc/zee3/zee3.env
    ```

    The S3 API listens on port 9000 on every address. The console listens only on
    `127.0.0.1:9001`, so from your computer use an SSH tunnel
    (`ssh -L 9001:127.0.0.1:9001 you@server`, then open `http://localhost:9001`) or put a
    [reverse proxy](/deploy/tls-and-proxies) in front.
  </Tab>
  <Tab title="Manual">
    <Steps>
      <Step title="Install the binary">
        ```bash
        curl -fsSL https://raw.githubusercontent.com/terrific-ci/z3/main/install.sh | sh
        ```

        See [Install](/deploy/install) for the options.
      </Step>
      <Step title="Create the user and directories">
        ```bash
        sudo useradd --system --home /var/lib/zee3 --shell /usr/sbin/nologin zee3
        sudo mkdir -p /var/lib/zee3 /etc/zee3
        sudo chown zee3:zee3 /var/lib/zee3
        ```

        If you use separate disks, give the `zee3` user their directories too
        (`sudo chown zee3:zee3 /mnt/disk1/zee3 ...`).
      </Step>
      <Step title="Create the settings file">
        Save this as `/etc/zee3/zee3.env`, with your own secret:

        ```bash /etc/zee3/zee3.env
        ZEE3_DATA_DIR=/var/lib/zee3
        ZEE3_S3_ADDR=0.0.0.0:9000
        # Keep the console on 127.0.0.1 behind a TLS reverse proxy.
        ZEE3_ADMIN_ADDR=127.0.0.1:9001
        ZEE3_PEER_ADDR=0.0.0.0:9002
        ZEE3_ACCESS_KEY=admin
        ZEE3_SECRET_KEY=a-long-random-secret

        # Erasure coding over several disks (order matters, can't change later):
        #ZEE3_DISKS=/mnt/disk1/zee3,/mnt/disk2/zee3,/mnt/disk3/zee3,/mnt/disk4/zee3
        # Let other nodes pull from this one:
        #ZEE3_PEER_TOKEN=
        #ZEE3_SITE_NAME=dc1
        #RUST_LOG=info
        ```

        ```bash
        sudo chown root:zee3 /etc/zee3/zee3.env
        sudo chmod 0640 /etc/zee3/zee3.env
        ```
      </Step>
      <Step title="Create the unit">
        Save this as `/etc/systemd/system/zee3.service`:

        ```ini /etc/systemd/system/zee3.service
        [Unit]
        Description=zee3 S3-compatible object storage
        After=network-online.target
        Wants=network-online.target

        [Service]
        User=zee3
        Group=zee3
        EnvironmentFile=/etc/zee3/zee3.env
        ExecStart=/usr/local/bin/zee3
        Restart=on-failure
        LimitNOFILE=65536

        [Install]
        WantedBy=multi-user.target
        ```

        This is the same unit the install script writes.
      </Step>
      <Step title="Start it">
        ```bash
        sudo systemctl daemon-reload
        sudo systemctl enable --now zee3
        systemctl status zee3
        ```
      </Step>
    </Steps>
  </Tab>
</Tabs>

## Change a setting

Edit `/etc/zee3/zee3.env` and restart:

```bash
sudo systemctl restart zee3
```

Every variable is listed in [Configuration](/deploy/configuration). Intervals, limits, CORS, region
and log levels can also be changed at runtime from the console's **Settings** page, without editing
the file (see [Settings](/operations/settings)).

<Warning>
  Don't change `ZEE3_SECRET_KEY` once the node holds data: user secrets and internal KMS keys are
  sealed with a key derived from it. See [Root credentials](/deploy/configuration#root-credentials).
</Warning>

## Logs

Zee3 logs to standard output, which systemd keeps in the journal:

```bash
journalctl -u zee3 -f
journalctl -u zee3 --since "1 hour ago"
```

`RUST_LOG` in `zee3.env` chooses what is logged (`info` by default, or a filter like
`warn,zee3_server=debug`). The console's **Logs** page shows recent and live log lines without a
shell on the server; see [Trace and logs](/audit/trace-and-logs).

## Stopping

`systemctl stop zee3` sends `SIGTERM`: Zee3 finishes the requests in flight, keeps unsent audit entries
for the next start, and exits.

## Hardening

The unit above is deliberately simple. If you add systemd sandboxing such as
`ProtectSystem=strict`, list every directory Zee3 writes to in `ReadWritePaths=`: the data directory
and every disk in `ZEE3_DISKS` or `ZEE3_POOLS`.

```ini
[Service]
NoNewPrivileges=yes
ProtectSystem=strict
ProtectHome=yes
PrivateTmp=yes
ReadWritePaths=/var/lib/zee3 /mnt/disk1/zee3 /mnt/disk2/zee3 /mnt/disk3/zee3 /mnt/disk4/zee3
```

Put these lines in a drop-in (`sudo systemctl edit zee3`) so the install script doesn't overwrite them
when you upgrade.

## Upgrading

Run the install command again, then restart the service:

```bash
curl -fsSL https://raw.githubusercontent.com/terrific-ci/z3/main/install.sh | sh -s -- --service
sudo systemctl restart zee3
```

The settings file is kept. Back up first; see [Upgrading](/deploy/upgrading).
