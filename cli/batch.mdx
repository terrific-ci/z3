---
title: "zee3 admin batch"
description: "Start, follow, cancel and remove batch jobs that replicate, expire or re-key many objects, or roll a bucket back to a point in time."
---

`zee3 admin batch` runs [batch jobs](/storage/batch): one-off work over many objects, in the
background on the node you talk to.

| Command | What it does | Right |
| --- | --- | --- |
| `zee3 admin batch list` | Jobs on the node, newest first | `admin:ServerInfo` |
| `zee3 admin batch start FILE [--wait]` | Start a job from a JSON definition (a file, or `-` for standard input) | `admin:ConfigUpdate` |
| `zee3 admin batch status ID` | One job's progress, last errors and dry-run samples | `admin:ServerInfo` |
| `zee3 admin batch cancel ID` | Stop a running job | `admin:ConfigUpdate` |
| `zee3 admin batch remove ID` | Forget a finished job | `admin:ConfigUpdate` |
| `zee3 admin batch rollback BUCKET --at TIME [--prefix P] [--key K] [--dry-run] [--wait]` | Roll a bucket, prefix or key back to a point in time, or preview it | `admin:ConfigUpdate` |

## Job definitions

A job is a JSON document with a `type`: `replicate`, `expire`, `rotate` or `rollback`.

<Tabs>
  <Tab title="expire">

```json expire-tmp.json
{
  "type": "expire",
  "source": { "bucket": "logs", "prefix": "tmp/" },
  "filter": { "older_than": "30d" },
  "versions": "all",
  "dry_run": true
}
```

`versions`: `current` (default; a delete marker in a versioned bucket), `noncurrent`, or `all`
(every version and delete marker). Versions held by Object Lock are skipped.

  </Tab>
  <Tab title="replicate">

```json replicate-archive.json
{
  "type": "replicate",
  "source": { "bucket": "medical-records" },
  "target": {
    "bucket": "archive", "prefix": "site-a/",
    "endpoint": "https://s3.dr-site.example", "region": "us-east-1",
    "access_key": "AKIAEXAMPLE", "secret_key": "..."
  }
}
```

Without `target.endpoint`, the target is a bucket on this cluster. `"overwrite": true` copies again
even when the target already has the same object.

  </Tab>
  <Tab title="rotate">

```json rotate-key.json
{ "type": "rotate", "source": { "bucket": "medical-records" }, "key_id": "records-key-2027" }
```

Without `key_id`, objects move to the default SSE-S3 key (`zee3-default`). `"dry_run": true` only
counts.

  </Tab>
</Tabs>

Every type takes an optional `filter`; all the conditions given must hold:

| Field | Meaning |
| --- | --- |
| `source.bucket` | Required: the bucket to go through |
| `source.prefix` | Only keys starting with this |
| `filter.tags` | Objects with all of these tags, like `{"kind": "scratch"}` |
| `filter.size_gt`, `filter.size_lt` | Larger or smaller than this many bytes |
| `filter.older_than`, `filter.newer_than` | Written at least, or at most, this long ago: `90s`, `15m`, `12h`, `30d`, `2w` |
| `filter.key_pattern` | Keys (after `source.prefix`) matching a glob: `*` any run of characters, `/` too; `?` one character |
| `filter.modified_after`, `filter.modified_before` | Written at or after, or before, this RFC 3339 time |

Before starting, Zee3 checks the definition: the bucket exists, a remote target answers, the KMS key
exists. A bad definition is refused and nothing runs.

## start

```bash
zee3 admin batch start expire-tmp.json --wait
```

```
started expire-146d75b7b7a2775c
expire-146d75b7b7a2775c      expire    running   matched 812  done 640  skipped 0  failed 0  163840000 bytes
expire-146d75b7b7a2775c      expire    done      matched 1204  done 1204  skipped 0  failed 0  246579200 bytes
```

Without `--wait`, the command prints the job id and returns. With `--wait`, it prints a progress
line every second until the job ends, then the job's last errors. It exits with status 1 when the
job fails.

A definition can come from standard input:

```bash
echo '{"type":"rotate","source":{"bucket":"medical-records"},"key_id":"records-key-2027"}' \
  | zee3 admin batch start - --wait
```

The progress line shows the job id, type and state (`running`, `done`, `failed`, `cancelled`), then:

| Count | Meaning |
| --- | --- |
| `matched` | Versions the filter selected |
| `done` | Copied, deleted or re-keyed (or would be, in a dry run) |
| `skipped` | Selected but left alone: already at the target, held by Object Lock, encrypted with a customer key |
| `failed` | Versions that failed; see `status` for the errors |
| `bytes` | Data handled |

## list

```bash
zee3 admin batch list
```

```
rotate-9f2c41d07ab3e815       rotate    running   matched 20311  done 9120  skipped 4  failed 0  0 bytes
replicate-51be0a77c9d2f043    replicate done      matched 1832  done 1790  skipped 42  failed 0  48213044221 bytes
expire-146d75b7b7a2775c      expire    done      matched 2  done 2  skipped 0  failed 0  400000 bytes
```

## status

```bash
zee3 admin batch status expire-146d75b7b7a2775c
```

```
expire-146d75b7b7a2775c      expire    done      matched 2  done 2  skipped 0  failed 0  400000 bytes
  would touch: tmp/a.log
  would touch: tmp/b.log
```

After the progress line come the job's message (why it failed, for example), up to 20 recent
errors (`error: ...`), and for a dry run up to 100 keys it would touch (`would touch: ...`).

## cancel

```bash
zee3 admin batch cancel rotate-9f2c41d07ab3e815
# rotate-9f2c41d07ab3e815: cancelling
```

Only a running job can be cancelled; otherwise the answer is `Error: the job is not running`.

## remove

```bash
zee3 admin batch remove expire-146d75b7b7a2775c
# expire-146d75b7b7a2775c: removed
```

A running job must be cancelled first. Removing forgets the job's record; what it did stays done.

## rollback

Rolls a versioned bucket, a prefix or one key back to how it looked at `--at`, any RFC 3339 time.
See [Point-in-time rollback](/storage/point-in-time).

```bash
zee3 admin batch rollback records --at 2026-11-18T09:30:00Z --prefix patients/ --dry-run
```

```
records at 2026-11-18T09:30:00Z: restore 3  delete 3  missing 1  unchanged 1  (8 keys changed since, 24 log entries read)
  restore  patients/del.txt (01a1ebdb32ad74bebf1338785669667b)
  delete   patients/gone.txt
  restore  patients/meta.txt (01a1ebdb32b87655abb391a2b5483abe)
  delete   patients/new1.txt
  delete   patients/new2.txt
  restore  patients/over.txt (01a1ebdb32a0728cbe0adecbef9c9ae2)
  missing  patients/purged.txt: the version current at that time was deleted since
```

`--dry-run` changes nothing and lists up to `--limit` planned changes (20 by default). Without it
the command starts a `rollback` job; `--wait` follows it like `start --wait`. `status` on a rollback
job also prints the keys per action and its changes:

```
rollback-cbebb96055763da2    rollback  done      matched 7  done 7  skipped 0  failed 0  12 bytes
  restore 6  delete 1  missing 0  unchanged 0
  change: restore patients/000.json (01a1ebe067f972fca9f0ac01e8e6a222)
  change: delete patients/README.txt
```

The same job as a definition for `start`:

```json
{ "type": "rollback", "source": { "bucket": "records", "prefix": "patients/" }, "at": "2026-11-18T09:30:00Z" }
```

`"key": "patients/001.json"` limits it to one key.

## Scheduling

Jobs run once. For a recurring job, start it from cron:

```bash
# Every night at 02:00, expire scratch files older than a week
0 2 * * * zee3 admin batch start /etc/zee3/expire-scratch.json
```
