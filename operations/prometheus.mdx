---
title: "Prometheus metrics"
description: "Scrape /metrics on the admin port: every metric z3 exposes, its type, labels and meaning."
---

Every node exposes Prometheus metrics at `/metrics` on the **admin port** (9001 by default). The
endpoint needs no sign-in, so Prometheus can scrape it directly.

```yaml prometheus.yml
scrape_configs:
  - job_name: z3
    metrics_path: /metrics
    static_configs:
      - targets: ["z3-jkt-1:9001", "z3-sby-1:9001", "z3-bdg-1:9001"]
```

<Warning>
  The admin port listens on `127.0.0.1` by default. For Prometheus on another host, set
  `Z3_ADMIN_ADDR=0.0.0.0:9001`, or scrape through a reverse proxy. `/metrics` lists bucket names
  and peer names, so keep it on a trusted network.
</Warning>

Counters count since the node started, as Prometheus expects; use `rate()` or `increase()` on
them. The replication link counters are the exception: they carry over restarts (see
[Replication](#replication)). The values are computed when Prometheus scrapes.

## Storage

| Metric | Type | Meaning |
| --- | --- | --- |
| `z3_buckets` | gauge | Number of buckets |
| `z3_objects` | gauge | Keys whose current version is a live object |
| `z3_logical_bytes` | gauge | Bytes of all stored versions, as clients see them |
| `z3_physical_bytes` | gauge | Bytes referenced in the chunk store after deduplication |
| `z3_chunks` | gauge | Referenced chunks |
| `z3_multipart_uploads` | gauge | Multipart uploads in progress |

`z3_logical_bytes / z3_physical_bytes` is the deduplication ratio.

## Disks and healing

| Metric | Type | Labels | Meaning |
| --- | --- | --- | --- |
| `z3_disk_online` | gauge | `disk`, `path` | `1` when the disk is usable, `0` when it is offline or foreign |
| `z3_heal_shards_repaired_total` | counter | | Shards or copies rewritten by [healing](/durability/healing) |
| `z3_heal_chunks_lost_total` | counter | | Chunks found with too few good shards to rebuild |
| `z3_orphan_chunks_deleted_total` | counter | | Unreferenced chunk files deleted by the [orphan sweep](/durability/healing#orphaned-chunks) |
| `z3_orphan_bytes_freed_total` | counter | | Bytes freed by the orphan sweep |

## S3 traffic

| Metric | Type | Meaning |
| --- | --- | --- |
| `z3_s3_requests_total` | counter | S3 requests since start |
| `z3_s3_client_errors_total` | counter | S3 requests answered with a 4xx status |
| `z3_s3_server_errors_total` | counter | S3 requests answered with a 5xx status |
| `z3_s3_received_bytes_total` | counter | Request body bytes received over S3 |
| `z3_s3_sent_bytes_total` | counter | Response body bytes sent over S3 |

Byte counts come from the `Content-Length` of requests and responses.

## Per bucket

Each series has a `bucket` label.

| Metric | Type | Meaning |
| --- | --- | --- |
| `z3_bucket_objects` | gauge | Live objects in the bucket |
| `z3_bucket_size_bytes` | gauge | Bytes of all stored versions in the bucket |
| `z3_bucket_requests_total` | counter | S3 requests for the bucket since start |
| `z3_bucket_errors_total` | counter | S3 requests for the bucket answered with an error |
| `z3_bucket_received_bytes_total` | counter | Bytes received for the bucket |
| `z3_bucket_sent_bytes_total` | counter | Bytes sent from the bucket |

Requests count for a bucket by their path (path-style addressing).

## Replication

One series per replication link, with `peer` and `bucket` labels. See
[Replication](/replication/overview). The counters of a link carry over restarts: each node saves
them every 30 seconds and at a graceful shutdown, so a crash loses at most the last 30 seconds.
They reset only when the link is removed.

| Metric | Type | Meaning |
| --- | --- | --- |
| `z3_replication_up` | gauge | `1` when the link is streaming |
| `z3_replication_paused` | gauge | `1` outside the peer's replication windows |
| `z3_replication_lag_entries` | gauge | Peer change-log entries not applied here yet |
| `z3_replication_lag_seconds` | gauge | Age of the oldest change not applied yet (0 when caught up) |
| `z3_replication_last_delay_seconds` | gauge | From the origin's commit to the local apply, for the last change |
| `z3_replication_applied_total` | counter | Changes applied from the peer |
| `z3_replication_conflicts_total` | counter | Concurrent writes resolved by HLC |
| `z3_replication_errors_total` | counter | Failed replication attempts |
| `z3_replication_bytes_wire_total` | counter | Bytes received over the network |
| `z3_replication_bytes_raw_total` | counter | Chunk bytes stored after decompression |
| `z3_replication_bytes_deduplicated_total` | counter | Chunk bytes not transferred because they were already here |
| `z3_replication_throttled_seconds_total` | counter | Time spent waiting for the peer's bandwidth limit |
| `z3_replication_geo_chunks_total` | counter | [Geo-erasure-coded](/replication/geo-erasure-coding) chunks for which only this site's shards were fetched |

## Example queries

```promql
# S3 requests per second, per node
sum by (instance) (rate(z3_s3_requests_total[5m]))

# Share of S3 requests answered with a 5xx
rate(z3_s3_server_errors_total[5m]) / rate(z3_s3_requests_total[5m])

# The ten busiest buckets
topk(10, rate(z3_bucket_requests_total[5m]))

# Disks that are offline
z3_disk_online == 0

# Replication links more than 5 minutes behind
z3_replication_lag_seconds > 300

# Links that are not streaming and not paused on purpose
z3_replication_up == 0 and z3_replication_paused == 0
```

For the raw format of the endpoint, see [Prometheus endpoint](/api/prometheus). For history
without Prometheus, z3 keeps its own [metrics](/operations/metrics) for up to three years.
